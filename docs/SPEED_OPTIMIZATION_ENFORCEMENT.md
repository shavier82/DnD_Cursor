# Speed Optimization Enforcement

## How Speed Optimization Rules Apply

### Understanding the Architecture

**Important Clarification:**
- The "agents" (REFEREE, NARRATOR, STATE_PATCHER, QA_COMPLIANCE) are **JSON outputs generated by the AI assistant**, not separate processes or agents
- The AI assistant creates these JSON files, then processes them using optimized PowerShell/Python scripts
- Speed optimization rules apply at **two levels**: AI assistant behavior (flags) and script code (optimizations)

### Enforcement Levels

#### 1. AI Assistant Level (`.cursorrules` enforcement)

**The AI assistant MUST follow these rules because:**
- `.cursorrules` file explicitly requires it
- Rules state: "THE AI ASSISTANT MUST always call scripts with FastMode flags"
- Rules are in the permanent configuration that the AI assistant reads

**What the AI assistant does:**
1. Generates 4 agent outputs (REFEREE, NARRATOR, STATE_PATCHER, QA_COMPLIANCE) as JSON files
2. **MUST call** `validate_agent_outputs.ps1 -SessionId <id> -FastMode -Quiet`
3. **MUST call** `merge_outputs.ps1 -SessionId <id> -FastMode`
4. **MUST call** `speak_narration.ps1 -SessionId <id> -Background` (if narration exists)

**This is enforced by `.cursorrules` section "SPEED OPTIMIZATION (CRITICAL - MANDATORY FLAGS)"**

#### 2. Script Code Level (already implemented optimizations)

**The scripts are already optimized in their code:**

1. **merge_outputs.ps1** - Patch application optimization:
   - Already converts state ONCE before loop, not per-patch
   - Already uses `-Compress` and `-NoNewline` flags for state save
   - Already conditionally spawns background jobs only if needed
   - These optimizations are IN THE CODE and will always be used

2. **validate_agent_outputs.ps1** - FastMode implementation:
   - Already has `-FastMode` flag that skips location fence checks
   - Already has `-Quiet` flag that suppresses verbose output
   - These optimizations are IN THE CODE and will always be used when flags are passed

3. **speak_narration.ps1** - Background mode implementation:
   - Already has `-Background` flag that runs TTS in non-blocking job
   - Optimization is IN THE CODE and will always be used when flag is passed

### How Rules Apply to "Agents"

**The "agents" (REFEREE, NARRATOR, STATE_PATCHER, QA_COMPLIANCE) are JSON files:**
- They don't have their own behavior - they're data structures
- The AI assistant generates them
- The optimized scripts process them

**So the rules apply by:**
1. AI assistant following `.cursorrules` → Always uses FastMode flags
2. Scripts being optimized in code → Always use optimized algorithms
3. Combination ensures speed optimizations are always applied

### Verification

**To verify rules are being followed:**

1. **Check AI assistant behavior:**
   - Look for `-FastMode -Quiet` flags in validate_agent_outputs calls
   - Look for `-FastMode` flag in merge_outputs calls
   - Look for `-Background` flag in speak_narration calls

2. **Check script code:**
   - merge_outputs.ps1 line 181-308: Patch application converts once (optimized)
   - merge_outputs.ps1 line 322: State save uses -Compress -NoNewline (optimized)
   - merge_outputs.ps1 line 329-352: Background jobs conditional (optimized)
   - validate_agent_outputs.ps1 line 68: FastMode skips location checks
   - speak_narration.ps1 line 147: Background mode spawns non-blocking job

3. **Measure performance:**
   - Turn processing should be <5 seconds (target: 2-4 seconds)
   - Validation should be ~0.5 seconds (with FastMode)
   - Merge should be 1-2 seconds (with FastMode)
   - TTS should be 0 seconds (background, non-blocking)

### Summary

**Yes, these rules will be adhered to by:**

✅ **The AI assistant** - Because `.cursorrules` explicitly requires it
✅ **The processing scripts** - Because optimizations are already in the code
✅ **Every turn** - Because rules are mandatory and in permanent configuration

**The rules are enforced at multiple levels:**
1. **Configuration level** (`.cursorrules`) - Tells AI assistant what to do
2. **Code level** (script implementations) - Optimizations are built in
3. **Workflow level** (turn processing) - Both work together for speed

**No separate "agent processes" to enforce rules on** - The agents are JSON outputs that are processed by optimized scripts following `.cursorrules` requirements.
